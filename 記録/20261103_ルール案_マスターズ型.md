# ルール案(マスターズ型)— 2026-11-03 案・未採用

**これは案です。** 2026-11-03 にたたき台として `ルール.md`(第 6 版)に入れた。以後は `ルール.md` を正とする。

採点を儲けに変え、過去の大会の形を土台にすることは決まっています(2026-11-03 主催決定)。
土台は「AI競馬予想マスターズ 2025 学生大会」の公式ルールです(https://yoso.sp.netkeiba.com/masters/ai2025_student/rule.html 、11/3 に読んだ要点は `進捗.md`)。

- 【マ】はマスターズと同じ所です。
- 【案】は、私たちに合わせて足したり変えたりした所です。マスターズは主催の API に賭けを登録する仕組みです。私たちは API の代わりに GitHub を使うので、その分を足しました。

今のルール(第 5 版)と第 6 版案から、次のものはなくなります: モデルの凍結、作り直しの確認、log loss と到達率、「そのレースのオッズ・人気は使わない」、前日 21:00 締切、共通の入力。

## 2. ポイントと賭け

- 開始時に、全員に 100 万 pt を配る。1 pt = 1 円の仮想のお金で、本物のお金は使わない。【マ】
- 券種は WIN5 以外すべて: 単勝・複勝・枠連・馬連・馬単・ワイド・3 連複・3 連単。【マ】
- 1 点は 100 pt 単位。【案】(マスターズには書いていない。本物の馬券に合わせた)
- 1 日に賭けてよいのは、その日の朝の残高まで。その日の払戻は、次の開催日から使える。【案】(マスターズは「次のレースから使える」。私たちはその日の賭けをまとめて出すので、こう変えた)
- 期間中に、合計 50 万 pt 以上を賭け、96 レース以上に賭ける。【マ】(マスターズは「50 万ポイント以上の投票必須」。賭けた額の合計と読んだ【案】)
- 残高が 0 になったら、それ以降は賭けられない。【案】

## 3. 賭けの出し方と締切【案】

1. その日の賭けを、CSV 1 本にまとめる: `bets/YYYYMMDD_名前.csv`
   - 見出し行: `race_id,券種,買い目,金額`
   - race_id: `YYYYMMDD-場名-R`(例: `20261114-東京-11`)
   - 買い目: 単勝・複勝は馬番 1 つ(`7`)。枠連・馬連・ワイド・3 連複は小さい順に `-` でつなぐ(`3-7`)。馬単・3 連単は着順に `>` でつなぐ(`7>3>1`)
   - 金額: 100 pt 単位
2. **締切**: その開催日の最初のレースの発走時刻の前まで。
3. 締切までに、CSV のハッシュを書いた `hashes/YYYYMMDD_名前.txt` を共有リポジトリに push する。締切前の最後の push を提出とする。締切は GitHub に記録された push の時刻で決める。
4. 締切の後、その日のうちに CSV 本体を push する。ハッシュと合わなければ、その日の賭けは無効(賭けなかった扱い)。
5. 出さなかった日は、賭けなかった扱い(残高は変わらない)。
6. 主催エージェントが、その日のハッシュのファイルに OpenTimestamps の時刻証明を付ける(だれでも後から確かめられるように)。

## 4. 使ってよい情報と手法

- 締切の時点で手に入る情報は、何を使ってもよい。そのレースのオッズ・人気(前日発売・当日朝のオッズ)も使ってよい。【案】(儲けで競うので、オッズは賭け方に欠かせない)
- 予想は機械学習のモデルで出す。条件分岐だけの手法(if 文だけ)は不可。LLM などの AI の手を借りて作ってよい。【マ】
- 賭けは、モデルとコードで決める。人が手で賭けを選んだり、直したりしない(自己申告)。【マ】(マスターズは「AI 以外での参加」を禁止)
- 参加者どうしで、コード・特徴量・予測・賭けを共有しない。【マ】
- 他人の予想(新聞・予想サイト・予想サービスの印や予想)を使うかは、話し合って決める(下の「決めること」)。

## 5. 採点

- 払戻は、JRA 公式の確定した払戻金を使う。当たった賭けは「金額 ÷ 100 × 100 円あたりの払戻金」を残高に足す。【案】
- 同着・特払いなどは、JRA 公式の払戻のとおりにする。取消・除外の馬を含む賭けは返す。【マ】(返し方の細かい所は JRA の決まりに合わせる)
- レースが中止になったら、そのレースの賭けは返す。【案】
- **順位: 11/29 の最後のレースが確定した後の残高が多い順。**【マ】
- 同点のときは、回収率(払戻の合計 ÷ 賭けの合計)が高い方を上にする。【案】
- 2 節の条件(50 万 pt・96 レース)を満たさなかった人は、満たした人の下に、残高の順で並べる。【案】
- 採点は、JRA 公式の成績ページを保存し、スクリプトで計算する。だれでも計算し直せるようにする。大会の前に、過去のレースで公式の払戻と 1 pt も違わないことを確かめる。
- 参考に、回収率と的中率も出す(順位には使わない)。

## 6. 大会後の発表【案】

- マスターズは入賞者が発表する。私たちは全員が、AI に作らせた短い資料を出す。人前で話す発表はしない(任意)。
- 資料は、主催が配る「発表のひな形」とプロンプトを、各自の AI(Claude Code など)に渡して作る。AI が自分のリポジトリ・開発ログ・賭けの CSV を読んで書き、本人は読んで直すだけでよい。
- 資料に入れること(マスターズの 3 点に 1 つ足した): 学習・検証に使ったデータの概要、何を予測したか(目的変数)、予測をどう賭け方に変えたか、AI の手をどう借りたか。
- 成績(残高の推移・回収率・的中率など)は、主催の採点スクリプトが全員分を作る。各自は書かなくてよい。
- 出し方: Discord の #結果 に、資料(PDF・スライド・Markdown のどれでも)を貼る。

## 決めること(話し合いが要る所)

1. 1 日に賭けてよい額を「その日の朝の残高まで」にしてよいか。
2. 他人の予想(新聞・予想サイトの印など)を、モデルの入力に使ってよいか。
3. 出さなかった日を「賭けなかった扱い」にしてよいか。
4. 同点と、条件を満たさなかった人の扱い。
5. 開発ログをどこまで書くか。公開のリポジトリに push すると、他の参加者からも見える。
6. おまけの「人間代表との 1 レース」を残すか。
7. 共有リポジトリへの push のやり方。リポジトリは公開したが、push できるのは共同編集者だけ(今は主催だけ)。全員を共同編集者にするか、別の形にするか。名前と GitHub のログイン名をどこに書くか。
8. 本番の前に予行をやるか(例: 11/8(日)の分で、賭けの CSV・ハッシュの push・採点を通す)。出し方が新しくなるので、1 回通しておきたい。
9. 趣旨の問いの書き直し。例: 「AI の手を借りて作った予想 AI で、2 週間の中央競馬で 100 万 pt をどこまで増やせるか」。
